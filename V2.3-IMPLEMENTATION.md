# CyberTech 360 V2.3 — Enterprise Intelligence & Evidence Automation

V2.3 adds evidence governance, reporting foundations, PCI requirement management, remediation SLA automation, notifications, vendor risk intelligence, BIA/BCP/DR records and an expanded tenant-grounded AI GRC Copilot.

## Database
Run after the V2.2 migrations:
1. `supabase/schema.sql`
2. `supabase/v2.2-production.sql`
3. `supabase/v2.2.1-security-hardening.sql`
4. `supabase/v2.2.2-compliance-engine.sql`
5. `supabase/v2.3-enterprise.sql`

## Edge Functions
Deploy `evidence-review`, `compliance-report`, `report-export`, `sla-notifications`, and the updated `ai-grc-copilot`.

## Evidence review
Evidence moves through pending_review -> approved/rejected/needs_update. Reviews are attributed to an authenticated reviewer and stored separately from the evidence object.

## Reporting
The compliance-report function provides an authenticated tenant-scoped report payload suitable for PDF/XLSX rendering by a trusted report worker. Do not generate compliance files from untrusted browser data.

## SLA automation
The `remediation_sla` view classifies open remediation records as overdue, due_soon or on_track. `create_sla_notifications()` creates daily notification records for items due within seven days. Schedule it with a trusted server-side scheduler after validating the target environment.

## Vendor risk
`vendor_assessments` records security score, inherent risk, residual risk and findings. `vendor_risk_summary` exposes the latest assessment per vendor.

## BIA / BCP / DR
`bia_processes` captures RTO, RPO, MTD, dependencies and recovery priority. `bcp_plans` and `dr_plans` track plan status, ownership, testing and next test dates.

## AI
Configure `AI_API_URL`, `AI_API_KEY` and `AI_MODEL` as server-side Edge Function secrets. Never expose the AI key in browser code.

V2.3 does not claim that a merchant is PCI compliant. It provides evidence, assessment and reporting workflows that support an authorized compliance program.


## PCI DSS 4.0.1
The requirement library is seeded with the 12 top-level PCI DSS requirements. PCI SSC states that v4.0.1 is a limited revision of v4.0; it did not add or delete requirements. The platform should still load exact requirement/sub-requirement wording from authorized PCI SSC assessment materials when conducting a formal assessment.
