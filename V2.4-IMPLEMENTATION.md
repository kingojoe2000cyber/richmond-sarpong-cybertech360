# CyberTech 360 V2.4 — Continuous Compliance & Security Operations

## Delivered
- Continuous control monitoring and monitoring-result history.
- Evidence-collection job framework that is connector-ready without pretending external systems are connected.
- CVSS-based vulnerability SLA calculation with tenant-configurable policies.
- Security KPI engine for control effectiveness, remediation backlog, overdue items, critical vulnerabilities and evidence readiness.
- Compliance schedule data model for recurring framework assessments.
- SIEM ingestion endpoint with tenant scoping and event de-duplication.
- Immutable evidence-chain ledger using previous-hash chaining and a restricted append function.
- Notification escalation worker.
- Cross-module AI GRC analyst grounded in risks, controls, vulnerabilities, evidence, remediations, metrics and SIEM events.
- Auditor evidence-review permission fix carried forward from V2.3.

## Deployment
1. Apply supabase/v2.4-continuous-operations.sql after V2.3 migrations.
2. Deploy the five V2.4 Edge Functions.
3. Configure SUPABASE_URL, SUPABASE_ANON_KEY and SUPABASE_SERVICE_ROLE_KEY.
4. Configure CRON_SECRET for scheduled workers and SIEM_INGEST_KEY for the SIEM endpoint.
5. Optionally configure AI_API_URL, AI_API_KEY and AI_MODEL.
6. Schedule continuous-monitor, evidence-collector and escalate-notifications with a production scheduler.
7. Create monitoring_checks and evidence_collection_jobs for each connected control/evidence source.
8. Connect a SIEM to siem-ingest and map source, event ID, timestamp, severity and event type.

## Security boundaries
- Service-role credentials remain server-side.
- Evidence-chain direct writes are revoked from authenticated clients.
- Tenant isolation is enforced by PostgreSQL RLS.
- AI analysis receives tenant-scoped records and must not fabricate compliance status.
- Connector-ready evidence automation does not claim live collection until a real connector is configured.

## KPI definitions
CONTROL_EFFECTIVENESS = average control effectiveness.
OPEN_REMEDIATIONS = active remediation count.
OVERDUE_REMEDIATIONS = active remediations past due.
CRITICAL_VULNERABILITIES = unresolved CVSS >= 9.
EVIDENCE_READINESS = approved/needs-update evidence readiness score.
